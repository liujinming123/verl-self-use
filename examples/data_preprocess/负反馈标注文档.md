# **用户****负反馈标注示例**

####             **（一）**     **背景****：**

​	用户使用语音助手过程中，会因为语音助手的功能不完善，体验差等原因，表达负面情绪。

算法能够捕捉用户的负面表达，进而挖掘出语音助手的功能不完善的具体场景。

​	但用户的负面表达并非全部是针对汽车或汽车语音助手本身的，需要人工标注训练数据和测试数据，供算法训练以区别用户针对汽车的负面表达和针对其他的负面表达。

####             **（二）**     **3****种****场景**

​            **1、**     **骂车机（重要）**

用户发出指令：”导航到乐歌大厦“，导航执行错误：”为您找到以下勒戈大厦“，用户表达负面情绪或吐槽：”滚/好傻/听不懂/怎么反应这么慢.....“

​            2、     骂人(骂其他)

用户发出指令：”打开车窗“，导航执行错误：”好的，为您打开车窗“，用户表达对其他事物的负面情绪或吐槽：”你这事办的真蠢/今天真衰“

指令执行后，指令执行正确无误，用户仍发出吐槽，则认为是语音助手延时聆听到的用户闲聊

​            3、     无

用户发出指令：”打开车窗“，导航执行错误：”好的，为您打开车窗“，用户未表达负面情绪：”不错不错“

指令执行后，指令执行正确无误，用户未发出吐槽

####             **（三）**     **标注****流程**

1、标注数据主要输入列：

| **context****（****上文****）**                    | **query** |
| -------------------------------------------------- | --------- |
| 用户: 安全带提示音取消响应: 语音暂不支持该功能哦。 | 操你妈    |

context在前，query在后，可以组成一段对话session

用户: 安全带提示音取消

响应: 语音暂不支持该功能哦。

用户: 操你妈

 

根据这段对话判断这属于3种场景的哪一类

 

2、主要输出列：

| 标注原因     | 标注分类 |
| ------------ | -------- |
| 无不文明用语 | 无       |

标注原因可选项见第四点标签说明

标签分类填写三种场景中的一种

 

​            3、     标注流程

标注人员可以假设自己是正在用车的车主，在与语音助手交互时经历一段context+query组成的对话

a)context中用户的话可能是给语音助手的指令，也可能是和其他乘客的闲聊，判断模糊时，更倾向于是给语音助手的指令

b)标签分类 骂车机和骂人判断模糊时，更倾向于判断骂车机

​      c)**希望随着标注的进行，标注人员能够不断补充对车上功能的了解****，****进而****提高****标注****准确率**

####             **（五）**     **特殊****示例****：**

​            4、     **【骂车机】****【****有不文明用语，****疑似****asr****识别****错误****】**

语音转文本错误场景：导航或者播放多媒体时，极有可能出现因asr(语音转文本识别)识别不准导致的差体验，这种只看文本会误认为是执行正确

​            a)     用户: 导航到勒戈大厦；响应: 为您找到以下勒戈大厦 用户：操你妈（用户实际想去乐歌大厦）

​            b)     用户: 播放大三；响应: 为您找到以下大三 用户：操你妈（用户实际想听《大山》）

上下文继承失败导致的负反馈，如下例，用户要上升悬架，语音助手未继承
